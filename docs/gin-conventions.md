# Gin 컨벤션

Gin의 "가볍고 명시적인" 철학을 따른다. 프레임워크가 숨겨서 처리해주길 기대하지 않고, 흐름을 코드에서 명시적으로 드러낸다.

- 핸들러는 얇게 유지한다. 비즈니스 로직은 핸들러가 아니라 별도 계층(service, queries)에 둔다.
- 요청 바인딩/검증은 `ShouldBindJSON`, `ShouldBindQuery` 등 Gin의 binding 기능을 사용한다. 수동 파싱하지 않는다.
- 에러는 발생 즉시 확인하고 바로 응답한다 (`if err != nil { c.JSON(...); return }`). 에러를 삼키거나 뒤로 미루지 않는다.
- 공통 관심사(로깅, 인증, recovery)는 핸들러에 중복 작성하지 않고 미들웨어로 뺀다.
- 라우트는 `Group`으로 버전/리소스 단위로 묶는다 (예: `/api/v1/users`).
- `gin.Context`는 요청 처리 범위를 벗어나 goroutine 등에 그대로 넘기지 않는다. 필요한 값만 꺼내서 넘긴다.
- 의존성(DB, Queries 등)은 전역 변수 대신 핸들러 구조체에 주입해서 사용한다.
- 상태 코드는 상황에 맞게 명시한다 (200/201/400/404/500 등 뭉뚱그리지 않음).
